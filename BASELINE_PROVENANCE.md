# Decision note — informal `baseline` provenance

**Status:** open. Found 2026-07-31 while preparing the GPT-5.6 generation run.
**Scope:** the informal register's `baseline` condition only.

---

## 1. What was found

The informal `baseline` condition is **not GPT-5.2**. It is **gpt-4o-mini**.

`data_utils.py` maps the informal baseline to the `generated_comment` column:

```python
INFORMAL_CONDITIONS = {
    "baseline": "generated_comment",     # <-- gpt-4o-mini, not GPT-5.2
    "human_like": "comment_human_like",
    "detector_aware": "comment_detector_aware",
    "detector_evasive": "comment_detector_evasive",
}
```

`make_balanced_quiz.py` maps the detection quiz's informal baseline to the same column.

### Provenance chain

| Step | File | Model |
|---|---|---|
| 1 | `llm_comments/generate_flashback_openai.py:39` | `model="gpt-4o-mini"` |
| 1b | `llm_comments/gather_reddit_comments_openai.py:58` | `model="gpt-4o-mini"` |
| 2 | writes column `Generated_OpenAI_Comment` | |
| 3 | `consolidate_informal_comments.py` renames it to `generated_comment` | |
| 4 | `consolidated_informal_comments_adversarial.csv` | consumed as "GPT-5.2 baseline" |

The three adversarial columns were generated separately, through
`generation_pipeline.py`, under GPT-5.2. Only `baseline` came from the older path.

### Why it was invisible

`COMMENT_PROMPT` in `generate_flashback_openai.py` is **byte-identical** to
`_INFORMAL_BASE` in `generation_pipeline.py`. The prompt is the same; only the model
differs. Nothing in the corpus, column names, or comments records the model.

### Evidence

Matching all 1,149 informal `generated_comment` texts against every candidate source
file in the repo:

| Source file | Model | baseline texts matched |
|---|---|---|
| `flashback_ai_comments.csv` | gpt-4o-mini | 676 |
| `LLM_consolidated_reddit_comments_MAY26.csv` | gpt-4o-mini | 187 |
| **confirmed gpt-4o-mini** | | **863 / 1,149 (75%)** |
| no source file located | unknown | 286 (276 flashback, 10 reddit) |

The same check on the adversarial columns matches 0/100 against those files, confirming
they came from the pipeline instead.

**What settles it is the caches.** Every generation cache
(`_gen_cache_adversarial.csv`, `_gen_cache_adversarial_gpt4omini.csv`) contains only
`human_like`, `detector_evasive` and `detector_aware` cells — **zero `baseline` cells**.
So the pipeline never generated an informal baseline under any model, and the only two
scripts that produce one (`generate_flashback_openai.py`,
`gather_reddit_comments_openai.py`) both hardcode `gpt-4o-mini`.

Therefore: **there is no GPT-5.2 informal baseline anywhere in the repo.** 75% of the
column is provably gpt-4o-mini; the remaining 286 come from a run whose output file was
not kept and cannot be shown to be any particular model.

The operative problem is not "the column is gpt-4o-mini" (75% proven, not 100%) but
"no part of the column is citable as GPT-5.2" — 863 are the wrong model and 286 are
unverifiable. Both disqualify it as the GPT-5.2 baseline, which is why the whole column
is regenerated rather than a subset.

Caveat on the 286: they are *probably* gpt-4o-mini too, on the reasoning above, but
that is inference, not measurement. Do not state it as fact in the thesis.

The formal register is unaffected: `Abstract_baseline` was always freshly generated by
`generation_pipeline.py` under GPT-5.2.

## 3. Decisions required

### D1 — Relabel, or regenerate?

- **(a) Relabel.** Report the informal baseline as gpt-4o-mini. Free. But leaves you
  with no GPT-5.2 informal baseline, so no within-model prompt-condition contrast in
  informal, and §4's model comparison stays partly gpt-4o-mini.
- **(b) Regenerate** a true GPT-5.2 informal baseline. Costs generation only.
- **Recommended: (b), and keep (a) alongside it** — see D3.

### D2 — If regenerating, at what scale?

| Option | Generations | Fixes |
|---|---|---|
| Quiz subset (`QUIZ_SUBSET=1`) | 300 calls (100 baseline cells) | the detection arm only |
| Full corpus | 3,447 calls (1,149 baseline cells) | detection **and** the §1–§4 feature analysis |

**Recommended: full corpus.** The feature analysis is the larger contribution and the
mislabelled column sits in it. Generation is the cheap half of the pipeline; judging
cost is unchanged either way because only 100 of those documents enter the quiz.

### D3 — Keep the legacy baseline as a documented generator?

**Recommended: yes, with an explicit verification caveat.** The existing 100 informal
baseline judgments remain valid data, and relabelling rather than deleting gives a third
generator at zero additional cost.

But of the 100 quiz baseline items, only **71 are positively traced to gpt-4o-mini
output files; 29 have no locatable source**. So a flat `gpt-4o-mini` label overstates
what is verified for roughly a quarter of them. Two defensible options:

- **(a) Label `gpt-4o-mini` with a footnote** stating that 863/1,149 corpus-wide (71/100
  in the quiz) are verified and the remainder are inferred from the fact that no
  baseline-generating script exists that is not gpt-4o-mini. Standard academic practice,
  keeps the table readable. **Recommended.**
- **(b) Label it `legacy-baseline`** and describe it as "produced by the pre-pipeline
  path, predominantly gpt-4o-mini". Maximally honest, but loses the clean
  model-generation narrative.

Either way, do **not** present the whole column as verified gpt-4o-mini.

### D4 — Stratify the quiz sample by platform?

The informal corpus is **952 flashback / 197 reddit** (17% reddit), but the 100-document
quiz sample is **67 flashback / 33 reddit** (33% reddit). The sample over-represents
Reddit roughly 2×.

**Recommended:** state it explicitly in the methods. Re-sampling would break pairing
with the already-judged GPT-5.2 items, so do not re-draw — document the imbalance and,
if reviewers press, report recall split by platform as a robustness check.

## 3b. Agreed run plan (settled 2026-07-31)

Probe evidence: `src/1_data_collection/refusal_probe_results.csv` (formal),
`refusal_probe_informal.csv` (informal). 20 and 15 generations per cell respectively.

| Register | GPT-5.2 refusals | GPT-5.6 refusals | GPT-5.6 markdown | GPT-5.6 structure | Verdict |
|---|---|---|---|---|---|
| formal | 0/20 | **5/20 (25%)** | 18/20 (90%) | ~75% headings + `Nyckelord:` footers, survives stripping | **excluded** |
| informal | 0/45 | 0/45 | 0/45 | none | **included** |

GPT-5.6 is therefore generated for the **informal register only**. Formal would have
measured formatting rather than Swedish, and was uninformative anyway — formal detection
is already at ceiling (Claude 100%, Gemini 96–100%), so every formal generator contrast
returns no-discordance. The 25% formal refusal rate (95% CI 11–47%) is reported as a
finding instead: newer model, more likely to decline detector-evasion prompting.

**Generation (OpenAI), 1,549 calls, ~$4–17:**

| # | Run | Calls |
|---|---|---|
| 1 | GPT-5.6 informal, 3 conditions × 100 quiz docs | 300 |
| 2 | GPT-5.2 informal baseline, 100 quiz docs | 100 |
| 3 | GPT-5.2 informal baseline, full 1,149-row corpus | 1,149 |

**Quiz: 406 items** — 300 GPT-5.6 + 100 corrected GPT-5.2 baseline + 6 markdown-stripped
re-judges of already-judged GPT-5.2 informal `human_like` items (originals 468, 618, 676,
701, 719, 789; superseded via the `supersedes` column).

**Judging: 406 × 3 = 1,218 calls, ~$40–70. Total ~$50–90.**

Interpretation caveat to carry into the write-up: GPT-5.6's informal comments average
464–533 chars against GPT-5.2's 926–1,111, where human comments average 269. GPT-5.6 is
1.7–2.0× human length, GPT-5.2 is 3.4–4.1×. Length may therefore *mediate* any
detectability difference — report mean length alongside recall rather than claiming 5.6's
Swedish is more human-like when "5.6 writes shorter, like humans do" may be the mechanism.

## 5. Prevention

`generated_comment` is the only text column in either corpus whose generating model is
not recorded anywhere. Going forward, `generation_pipeline.py` writes per-model columns
(`comment_baseline`) and per-model filenames, so this cannot recur silently — but the
legacy column keeps its ambiguous name. Consider renaming it
`generated_comment_gpt4omini` once the dependent scripts are updated.
